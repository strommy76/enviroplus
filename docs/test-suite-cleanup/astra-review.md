## F1 — CONFIRMED, low: corrected screen fixture still combines impossible history lengths

Location: tests/test_screens.py:94–98, particularly new gas_hist construction at96. Actual production: enviro_dash3.py:333–336,440–444,454–457.

Both PM and gas deques begin empty, have the same maximum length and append once during every completed loop before any render. Therefore their lengths are equal at every real render. Before those deques fill, CO2 history has at most one entry for each completed prior loop: the first loop cannot close a pending interval. With four PM entries, gas must also have four, and CO2 history can have at most three.

The shared fixture currently gives each PM history four entries, each gas history three, and CO2 history four, for both present=True and present=False. I evaluated only the pure _state function extracted with AST: both branches returned PM lengths[4,4,4], gas lengths[3,3,3], CO2 length4. This does not require executing the suite or hardware code. Source confirms the cardinality invariant. The new gas length3 creates another unreachable component while repairing the original unreachable NULL gas values; the CO2 length issue was already present in this same helper.

Impact is limited to fidelity of the twelve screen cases using this helper. No current rendering failure or production regression is claimed. The approved work expressly repairs this shared helper to represent reachable production state, and AGENTS.r requires possible counterpart behavior. This is a tiny completion of that correction, not a request for new scenarios or a fixture framework.

Minimum correction: make the histories represent one common reachable point in the loop. For example retain the existing four-entry CO2 history and add one older PM entry so each PM history has five, then make each gas history five numeric entries. Five successful loop frames can have four closed intervals; current CO2=612 may legitimately differ from the latest closed interval=640. Alternatively use four PM/gas entries and at most three CO2-history entries while retaining a real gap. Do not force CO2 current/history equality: production deliberately keeps different sampling semantics.
