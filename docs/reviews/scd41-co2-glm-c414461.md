## Findings

### F1 — PMS5003 frame-word mapping: the Tier 1→Tier 2 boundary contract is self-contradictory and unvalidated against the pinned driver — primary-metric corruption plausible, and the suite cannot see it

**Severity: CRITICAL (conditional; one command settles it). Status: CONFIRMED (contract indeterminacy and test-power defect, from content); live-data-corruption sub-claim UNCONFIRMED pending that command.**

The retain side and the derive side of the same boundary describe different bytes:

- Retain side — `enviro_dash3.py`, `read_sample()`: `sample["pms5003_frame_hex"] = bytes(pms5003_sensor.read().raw_data).hex()`. The plan (`docs/reviews/scd41-co2.md`, "What changed") calls this "**The checksummed PMS5003 frame** as bytes"; `local_sensors.py`'s header comment says the frame is retained "as **the bytes the driver checksummed**". A PMS5003 frame that carries its checksum is the 32-byte protocol frame beginning `0x42 0x4D` then the length word `0x001C` — the PMS5003 checksum is defined over those start bytes. The driver's own validation (this code imports `ChecksumMismatchError` from `pms5003` and catches it) only works on a frame that includes them.
- Derive side — `local_sensors.py`, `_pms_words()` (docstring: "**The frame's 14 big-endian words**, the layout PMS5003Data unpacks") unpacks the retained bytes **from offset 0**, and `_PMS_STANDARD = {"pm1": 0, "pm25": 1, "pm10": 2}  # PMS5003Data.data indices` takes words 0–2.

These cannot both be true. If the retained `raw_data` is the checksummed frame, it is 16 words, and words 0–2 are `0x424D` (16973), the length word (28), and the PM1-standard value — so every derived row would carry `pm1 = 16973.0`, `pm25 = 28.0`, `pm10 = <PM1 standard>`: garbage in the primary AQI metric, silently, live *and* on replay (replay reproduces the same garbage faithfully, so the deployed-effect check "replaying a finished day reproduces the live rows" would **pass** and mask it). If `raw_data` is instead the header-less 14-word body, the projection stands — but then the artifact's own "bytes the driver checksummed" description is false. The projection is correct only under the reading its own Tier 1 description excludes.

Nothing in the artifact shows the layout was ever observed from the real driver, and the test bakes in the unvalidated model:

- `tests/test_dash_loop.py`, `frame()`: `struct.pack(">14H", pm1, pm25, pm10, ...)` — a 28-byte, header-less, length-less frame; the `PMS5003` stand-in returns it as `raw_data=bytearray(outcome)` with no header/checksum validation. Under doctrine r a stand-in may substitute only with behavior the real counterpart can produce; this shape matches the implementation's assumption, not the pinned `pms5003==1.0.1`. Consequently the recorded violation power ("PMS atmospheric words used → 2 failed") is power against the model only — I dispute that row's evidentiary scope, not its arithmetic.
- The values-table premise "PMS words 0–2 | `PMS5003Data.pm_ug_per_m3(size)` default" is likewise unvalidated: if the library default is `atmospheric=True` (my recollection; not verifiable here), the previous live code stored the *atmospheric-environment* words, and this projection — even with the offset corrected — silently switches the metric to the *standard-particle* words at the cutover. UNCONFIRMED, same command settles it.

**The check that settles it** (against the pinned `pms5003==1.0.1`, one command): inspect `PMS5003Data.__init__` / `raw_data` (or any real frame): if `raw_data` begins `42 4d`, fix `_PMS_STANDARD` to the physical standard words (frame byte offsets 4–9, i.e. words 2–4) and give the stand-in the real 32-byte shape including header, length and checksum word; also determine which word set `pm_ug_per_m3`'s default returns so the cutover preserves the metric's meaning.

**Fix cost vs. what it prevents:** trivial (an index shift, a test-frame shape, and confirming the default's word set) against a silent break of the dashboard's primary metric. Tier 1 mitigates the blast radius — the frames are retained correctly, so a wrong projection is repaired by fix-plus-replay — but the entire point of the retained-frame design is that the projection is validated against the driver, and here it is not. The branch's own research table validated the SCD41 driver live; the PMS layout premise got no equivalent check despite the code re-implementing the driver's unpacking (doctrine h's search-and-validate burden, met for the SCD41, not met here).
